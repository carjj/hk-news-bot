令新聞準點到分鐘，兼防止 GitHub 因 60 日冇活動而停用排程

💡 點解要兩個一齊用？
GitHub Actions 內置 croncron-job.org
準時度繁忙時延遲 5–30 分鐘準點到分鐘 ✅
repo 60 日冇活動GitHub 會自動停用照 ping 唔受影響 ✅
呢個方案嘅角色後備（每小時 08 分）主力（每小時 00 分）
我已經喺程式加咗「最短推送間隔鎖」（預設 45 分鐘） —— 所以兩邊同時觸發都唔會重複推兩次，邊個先到邊個推，另一個會自動跳過。
1

開一條 GitHub Personal Access Token（PAT）

畀 cron-job.org 一個「撳掣」嘅權限，只限 Actions

  1. 去 github.com/settings/personal-access-tokens （Settings → Developer settings → Personal access tokens → Fine-grained tokens）
  2. 撳 Generate new token
  3. 填：
    Token namecron-job-news
    Expiration揀 1 年（最長 1 年，到期要換）
  4. Repository access → 揀 ● Only select repositories → 揀你個 hk-news-bot
  5. Permissions → Repository permissions → 搵到 Actions → 揀 ● Read and write
    ⚠️ 只開 Actions 就夠，千祈唔好開多。
    如果之後試跑出現 403 Resource not accessible， 就返嚟加埋 Contents: Read and write。
  6. 撳 Generate token → 即刻抄低（開頭係 github_pat_）

3

去 cron-job.org 開一個 Cronjob

免費，唔使信用卡

  1. 去 cron-job.org → 右上角 Sign up（email 註冊，要收驗證信）
  2. 登入 → 左邊 Cronjobs → 撳 CREATE CRONJOB
  3. 填以下資料：
cron-job.org · Create cronjob
Title每小時中文新聞
URL https://api.github.com/repos/OWNER/REPO/actions/workflows/hourly-news.yml/dispatches
Request method
● POST　○ GET
Schedule
Every 1 hour(s) ▾　at minute 0
Timezone: Asia/Hong_Kong ▾ （冇嘅話揀 UTC，然後 hour 減 8）
CREATE

跟住撳 「ADVANCED」／「Headers & Body」 展開，填呢啲：

① Request headers（要加 4 條）
Accept: application/vnd.github+json Authorization: Bearer github_pat_XXXXXXXXXXXXXXXXXXXX X-GitHub-Api-Version: 2022-11-28 Content-Type: application/json
⚠️ 第二行 Bearer 後面貼你第 1 步抄低嘅 token， Bearer 同 token 之間要有一個空格。
② Request body
{"ref":"main"}
⚠️ main 要同你 repo 嘅分支名一致。 去 GitHub repo 主頁睇左上角個分支名：如果係 master 就要寫 {"ref":"master"}。
4

試跑，確認成功

30 秒內知結果

  1. 喺 cron-job.org 個 cronjob 入面，撳 TEST RUN（或 Run now）
  2. 睇結果：
    HTTP 狀態204 No Content ✅
    意思GitHub 收到指令，成功觸發
  3. 返去 GitHub → Actions 頁，應該見到一個新嘅 run， 觸發方式寫住 workflow_dispatch
  4. 等 30–60 秒 → Telegram 收到新聞 🎉
❌ 出錯點算？
HTTP / 錯誤原因點執
401 Bad credentialsToken 錯／過期／抄漏重新 generate token，注意要有 Bearer 同空格
403 Resource not accessible權限唔夠PAT 要有 Actions: Read and write；得唔到就加埋 Contents: Read and write
404 Not Found網址錯檢查 OWNER／REPO 有冇打錯；workflow 檔名一定要 hourly-news.yml
204 但 Actions 冇反應分支名錯body 嘅 ref 要改做你實際分支名（main / master）
422body 格式錯一定要 {"ref":"main"}，雙引號，唔可以單引號
✓

之後實際會點運作？

兩個 trigger，一個鎖，唔會重複

時間（HKT）邊個觸發結果
13:00cron-job.org（主力）✅ 推送
13:08GitHub Actions 內置 cron（後備）⏸️ 距上次 8 分鐘 < 45 → 自動跳過
14:00cron-job.org✅ 推送
—cron-job.org 死機嗰陣✅ 13:08 / 14:08 嗰個後備會頂上
🎉 即係：邊個先到邊個推，另一個自動讓開 間隔鎖嘅分鐘數可以改：config.yaml 嘅 min_interval_minutes: 45，或 GitHub Variables 加 MIN_INTERVAL_MINUTES。
想兩個 trigger 都出到嘢（例如半個鐘一次）就改細佢，例如 25。
💡 cron-job.org 嘅限制（對我哋冇影響） 30 秒連線逾時 —— 但我哋只係叫 GitHub「開始跑」，GitHub 秒回 204， 唔會等 workflow 跑完，所以完全冇問題。
免費版最短 1 分鐘一次；我哋一小時一次，綽綽有餘。
🔔 建議開埋失敗通知 cron-job.org 個 cronjob 入面有 Notifications， 可以設定失敗時 email 通知你 —— 咁 GitHub 嗰邊出事你就即刻知。
